## Assessment

The original office is a compelling home screen. The building now uses its canvas, materials, characters, lighting and HUD rather than looking like a separate product. Character save correctly closes the editor and returns to the office. Invitations make presence/activity scope explicit; friend visits omit the owner's private cost and transcript panels. Access failure and revocation regressions already have useful behavioral coverage.

This is a functioning local prototype, not a public-service release. A bounded review cannot establish exhaustive security, accessibility, browser compatibility or performance certification. The biggest product gap is a reason for friends to return after the first visual tour.

## Confirmed defects repaired in this pass

1. **P1 — Late account mutations could render another account's credentials.** A delayed publisher-key or invitation response could populate the newly signed-in account's current panel; a late office-name response could restore stale account state. Added generation checks to authentication and account-scoped mutation results, connected-panel checks before displaying secrets, and disabled duplicate key creation while pending. Synthetic browser regressions delay Alice's key/invite/name responses until Bobby is signed in, then assert no old secret appears and Bobby remains the displayed account. This fixes in-page response handling; it does not claim cross-tab session synchronization.
2. **P2 — Same-size usage-log rewrites could preserve stale tokens.** A rewrite before the 64-byte checkpoint boundary could be missed if file size and the final boundary bytes were unchanged. Changed modification time at identical size now forces a complete rescan, for both live and saved checkpoints. A synthetic regression changes 30 input tokens to 90 without changing the tail or file length. Arbitrary earlier edits combined with an append remain outside the boundary guard's guarantee; documentation now states that limit.
3. **P2 — Owner floor incorrectly said “Activity shared”.** Owner detail now says “Your office · invited access only”, without implying publishing is enabled. Visitor labels still reflect their actual grant scope; online/offline remains separately reported. English and German updated.
4. **P2 — Vertical swipe could select a floor.** Picking now checks movement on both axes and cancels interrupted gestures. The real-WebGL mesh-picking regression first performs a vertical drag and asserts no selection, then verifies a real click still works.
5. **Documentation consistency.** SECURITY.md now includes bounded character appearance and allowlisted room preferences in its sharing description.

## Differentiation: recommended direction

**Positioning hypothesis: “A private neighborhood for people building with AI.”** The value is social connection plus owner control over visibility, with the original office as its recognizable visual identity. This is a hypothesis to test, not a claim of an industry first.

Pixel agent offices, status displays and guest agents already exist in [Star Office UI](https://github.com/ringhyacinth/Star-Office-UI). Human virtual-office presence and casual collaboration are established in [Gather](https://www.gather.town/virtual-office). Agent-office desktop scenes, customization and integrations also appear in [Bagidea Office](https://bagidea.github.io/bagidea-office/docs.html). These primary sources show why prettier rooms and more status counters alone are a weak distinction; this was a focused scan, not an exhaustive market study. Do not copy their artwork or assume matching licenses.

Proposals, not implemented features:

1. **Build together.** Friends opt into a 25/50-minute focus session in their offices or a shared rooftop. Show consented human presence, a gentle start/finish ritual and optional check-in. No prompt streaming or remote control; include quiet mode. This gives the building a recurring purpose.
2. **“We shipped” moments.** An owner approves a safe milestone card, then the building lights up briefly and friends can react. Export a short replay/card with a preview and explicit sharing choice. Use manual owner publication or genuinely verified milestones; agent activity alone is not proof of completed work. Any milestone metadata needs a new explicit allowlist/consent decision.
3. **A great 30-second first tour.** Keep a clearly synthetic, one-click playable two-office demo and explain invite → visit → return home. Later add shareable building clips with owner-selected fields. Public hosting remains a separate authorized release.
4. **Recognizable personal floors.** Earned or chosen decor, named offices and a small set of allowlisted furniture placements make each floor memorable. Favor a cohesive identity over hundreds of cosmetic settings.
5. **A polite doorbell.** Invite-only visitors can ask to join a focus session; owners can allow, decline or silence it. Add human avatars only if trials show they improve connection. No open unsolicited chat or visitor surveillance.

Recommended order: fix the P2 usability items → trial with five developer friend pairs → implement one thin “Build together” flow → add an owner-approved shareable milestone if participants want to show it. Observe successful first invitations, confusion about visibility and whether pairs voluntarily return. Avoid token-spending leaderboards and superficial agent counts as success metrics.
